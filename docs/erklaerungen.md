# Erklärungen zu den Fragen des Antrags auf ein neues IuK-Projekt

Je Frage aus `docs/antragsfragen.md` eine kurze Erklärung für jemanden, der zum ersten Mal einen IuK-Antrag stellt.

| Nr | Erklärung |
|---|---|
| K1 | Tragen Sie das Datum ein, an dem Sie den Antrag ausfüllen. Es hilft, verschiedene Fassungen des Antrags auseinanderzuhalten. |
| K2 | Wählen Sie „Einführung“, wenn eine Software oder ein IT-Dienst neu an der FAU eingesetzt werden soll. Wählen Sie „Einstellung“, wenn ein bestehendes System abgeschaltet werden soll. |
| K3 | Nennen Sie das Produkt oder den Dienst mit seinem gebräuchlichen Namen, bei gekaufter Software auch den Hersteller. Dieser Name bezeichnet im weiteren Antrag das „IuK-Projekt“. |
| A1 | Nennen Sie die Person, die das Vorhaben fachlich verantwortet (Product Owner), mit ihrer Funktion und ihrer Einrichtung, etwa Lehrstuhl, Department oder zentrale Einrichtung. Diese Person ist Ansprechpartnerin für Rückfragen des CIO-Gremiums. |
| P1 | Beschreiben Sie, was beschafft oder eingeführt werden soll und welches Problem es lösen soll. Eine gute Antwort nennt den fachlichen Zweck und den erwarteten Nutzen in wenigen Sätzen. |
| P2 | Beschreiben Sie, wer die Software wie oft und in welchem Umfang nutzt, zum Beispiel täglich in der Verwaltung oder einmal im Semester für Prüfungen. Nennen Sie auch den geplanten Zeitraum, etwa eine Erprobung von einem Jahr oder einen dauerhaften Betrieb. |
| P3 | Nennen Sie die Arten von Daten, die im System selbst angelegt und gepflegt werden, zum Beispiel Personendaten, Forschungsdaten, Termine oder Dokumente. Eine grobe Einordnung genügt, eine vollständige Feldliste ist nicht nötig. |
| P4 | Nennen Sie die Systeme, aus denen Daten übernommen werden, und die Systeme, an die Daten weitergegeben werden. Geben Sie, wenn bekannt, auch an, wie der Austausch erfolgt, etwa über eine Schnittstelle oder als Dateiexport. |
| P5 | Eine Skizze zeigt, welche Systeme, Dienste und Abläufe miteinander Daten austauschen und in welche Richtung. Kreuzen Sie das Kästchen an, wenn Sie eine solche Skizze dem Antrag beifügen. |
| P6 | Unterlagen des Anbieters wie Produktbeschreibungen oder Präsentationen helfen dem Gremium, das Vorhaben einzuschätzen. Kreuzen Sie das Kästchen an, wenn Sie solche Unterlagen beifügen. |
| D1 | Personenbezogen sind nach der Datenschutz-Grundverordnung (DSGVO) alle Angaben, die sich auf eine bestimmte oder bestimmbare Person beziehen, etwa Name, E-Mail-Adresse, Matrikelnummer oder IP-Adresse. Wählen Sie „Ja“, sobald das System solche Daten speichert oder verarbeitet, auch wenn es nur Anmeldedaten sind. |
| D2 | Geben Sie an, ob der/die Datenschutzbeauftragte der FAU bereits von dem Vorhaben weiß. Werden personenbezogene Daten verarbeitet, ist es sinnvoll, ihn oder sie früh einzubeziehen. |
| D3 | Gemeint ist eine schriftliche Einschätzung des/der Datenschutzbeauftragten der FAU zu dem Vorhaben. Wählen Sie, ob sie dem Antrag beiliegt, später nachgereicht wird oder nicht vorliegt. |
| R1 | Nach der IT-Rahmendienstvereinbarung (IT-RDV) brauchen bestimmte IT-Systeme die Zustimmung des Personalrats oder der Schwerbehindertenvertretung, etwa wenn sie Verhalten oder Leistung von Beschäftigten erfassen können. Wählen Sie „Ja“, wenn das System von Beschäftigten genutzt wird oder Daten über sie verarbeitet und Sie eine Zustimmung für nötig halten. |
| R2 | Geben Sie an, ob die Personalvertretung oder die Schwerbehindertenvertretung bereits über das Vorhaben informiert ist. |
| R3 | Gemeint ist eine schriftliche Äußerung der Personal- oder Schwerbehindertenvertretung zu dem Vorhaben. Wählen Sie, ob sie dem Antrag beiliegt, später nachgereicht wird oder nicht vorliegt. |
| B1 | Nach § 9 der Bayerischen Digitalverordnung (BayDiV) müssen Angebote der Informationstechnik barrierefrei sein, also den Anforderungen der Web Content Accessibility Guidelines (WCAG) entsprechen. Wählen Sie „Ja“, wenn der Anbieter dies zusichert oder belegt, etwa durch eine Erklärung zur Barrierefreiheit oder einen Prüfbericht. |
| I1 | Der Schutzbedarf beschreibt, wie schwer ein Schaden wäre, wenn eines der drei Schutzziele verletzt wird: Vertraulichkeit (nur Berechtigte sehen die Daten), Integrität (die Daten sind richtig und unverändert) und Verfügbarkeit (das System ist nutzbar, wenn es gebraucht wird). Geben Sie für jedes Schutzziel eine Stufe an: normal, hoch oder sehr hoch, und begründen Sie sie kurz. |
| I2 | Das Bundesamt für Sicherheit in der Informationstechnik (BSI) beschreibt in Mindeststandards grundlegende Anforderungen an die Sicherheit von IT-Systemen. Wählen Sie „Weiß ich nicht“, wenn Sie dazu keine Aussage des Anbieters haben; das RRZE kann bei der Einschätzung helfen. |
| I3 | Ein Sicherheitskonzept beschreibt, wie das System gegen Angriffe, Datenverlust und Ausfälle geschützt wird, zum Beispiel durch Verschlüsselung, Rechtevergabe, Datensicherung und regelmäßige Updates. Geben Sie an, ob es ein solches Konzept gibt, wer es erstellt hat und ob es aktuelle Sicherheitstechnik berücksichtigt. |
| Z1 | Nennen Sie die Gruppen, die das System nutzen, etwa Studierende, Beschäftigte oder Externe, und ihre Rollen, zum Beispiel lesend, bearbeitend oder verwaltend. Eine ungefähre Zahl der Nutzenden ist hilfreich. |
| Z2 | Beschreiben Sie, wie Konten angelegt, Rechte vergeben und wieder entzogen werden. Geben Sie an, ob die Anmeldung über die zentrale Benutzerverwaltung der FAU erfolgen soll oder über eigene Konten im System. |
| U1 | Geben Sie Ihre Einschätzung, ob die vorgesehenen Nutzenden das System ohne große Einarbeitung bedienen können. Grundlage kann etwa eine Vorführung, eine Testphase oder die Erfahrung anderer Einrichtungen sein. |
| U2 | Gemeint sind Hilfen wie Benutzerhandbücher, Online-Hilfen und Betriebshandbücher, die zur jeweils eingesetzten Version passen. Wählen Sie „Ja“, wenn sie mindestens auf Englisch, besser auf Deutsch vorliegen. |
| V1 | Geben Sie an, ob Sie über das Vorhaben bereits mit Fakultäten oder dem RRZE gesprochen haben, etwa weil dort ähnliche Systeme genutzt oder betrieben werden. |
| V2 | Nennen Sie die Gesprächspartner, also Einrichtung oder Funktion, und das Ergebnis der Gespräche in wenigen Sätzen. Diese Frage ist Pflicht, wenn Sie V1 mit „Ja“ beantwortet haben. |
| V3 | Geben Sie an, ob Sie geprüft haben, ob ein System, das an der FAU bereits im Einsatz ist, den Zweck erfüllen könnte. So lassen sich doppelte Systeme und Kosten vermeiden. |
| V4 | Nennen Sie die geprüften Systeme und den Grund, warum sie nicht passen, etwa fehlende Funktionen oder ungeeignete Lizenzbedingungen. Diese Frage ist Pflicht, wenn Sie V3 mit „Ja“ beantwortet haben. |
| E1 | Nennen Sie die Person oder Einrichtung, die die Einführung des Systems plant und verantwortet, bis es in Betrieb ist. |
| E2 | Nennen Sie, wer das System nach der Einführung dauerhaft betreibt, zum Beispiel Ihre Einrichtung, das RRZE oder ein externer Anbieter. Bei einem externen Anbieter beschreiben Sie kurz, warum er voraussichtlich langfristig am Markt bleibt, etwa durch Größe, Kundenstamm oder langjährige Erfahrung. |
| E3 | Nennen Sie, wer entscheidet und beauftragt, dass das System an neue Anforderungen angepasst oder erweitert wird. |
| E4 | Nennen Sie, an wen sich Nutzende bei Fragen oder Störungen wenden können, und wer technische Probleme behebt. Unterscheiden Sie, wenn nötig, zwischen Hilfe für Nutzende und technischem Support durch den Hersteller. |
| E5 | Nennen Sie, wer dafür sorgt, dass Sicherheits- und Produktupdates aller Bestandteile, etwa Software, Betriebssystem und Datenbank, regelmäßig eingespielt werden. Veraltete Komponenten sind ein häufiges Sicherheitsrisiko. |
| C1 | Nennen Sie die einmaligen Kosten für Anschaffung und Einrichtung, einschließlich des Personalaufwands, und die laufenden Kosten pro Jahr, etwa Lizenzen, Wartung und Betrieb. Schätzungen sind in Ordnung, wenn Sie sie als solche kennzeichnen. |
| C2 | Geben Sie an, aus welchen Mitteln die Kosten bezahlt werden, zum Beispiel aus dem Haushalt Ihrer Einrichtung, aus Drittmitteln oder aus zentralen Mitteln. |
| C3 | Ab bestimmten Auftragswerten schreibt das Vergaberecht eine Ausschreibung vor. Wenn Sie unsicher sind, klären Sie die Frage mit der für Beschaffung zuständigen Stelle der FAU. |
| C4 | Geben Sie an, ob durch das neue System an anderer Stelle Kosten oder Aufwand wegfallen, etwa weil ein altes System abgeschaltet wird oder Arbeitsschritte entfallen. |
| C5 | Beschreiben Sie, was eingespart wird, zum Beispiel Lizenzkosten oder Arbeitszeit, und schätzen Sie den Umfang. Diese Frage ist Pflicht, wenn Sie C4 mit „Ja“ beantwortet haben. |
| C6 | Tragen Sie das Datum ein, an dem Sie den Antrag beim CIO-Office einreichen. |
